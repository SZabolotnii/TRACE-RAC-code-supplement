# LLM-held-out protocol v1 — 23.09.2026

Мета: порівняти нову дослідницьку реалізацію RAC із повноцінним stateful workflow engine на нових синтетичних coding-трасах, використовуючи два сліпі LLM-маркування. Не є rerun приватного TRACE-AI-gate. Нульова різниця допустима; перевага не є умовою успіху. Не називати LLM людськими доменними експертами.

Послідовність: (1) зафіксувати POLICY та протокол; (2) створити окремі реалізації RAC і baseline та development-траси; (3) перевірити на development, записати SHA256 реалізацій і політики; (4) лише потім окремий агент створює 24 test-епізоди без читання реалізацій чи dev-трас; (5) два нові судді незалежно читають тільки POLICY та анонімізовані test-траси без family/split/expected; (6) зафіксувати мітки до виконання test; (7) виконати обидва плеча; (8) звітувати всі розбіжності, без правок під test. Якщо потрібна правка після test, звітувати вихідний результат і називати повтор exploratory.

Baseline має незалежний reducer/стан, повну шістку версій із ABA-інвалідацією, review lifecycle, capacity, TTL/deadline, бюджет повторів і всі ті самі detector outputs. Заборонено імпортувати RAC чи реалізовувати baseline його абляцією. Shared runner може лише подавати однакові події й збирати виходи.

Train/dev охоплює прості одиничні функції. Test має нові комбінації/порядок подій, а не копії 18 попередніх трас чи dev зі зміненими назвами. Це prospective holdout від реалізаторів, не випадкова вибірка з реальної популяції; primitive rules спільні навмисно. Тестовий генератор працює після freeze реалізацій. Один coding-домен, 24 епізоди, всі attempts аналізуються; жодних CI/p-values для цього синтетичного набору.

Два окремі LLM-судді без історії, із забороною читати реалізації/мітки колеги. Модельна родина може збігатися: це session independence, не незалежність помилок. Точні snapshot/sampling недоступні. Зберігати запити, мітки та підстави. Primary oracle — тільки consensus allow/review/block обох; незгоду й insufficient_information зберігати, виключати з primary denominator і показувати sensitivity проти кожного судді. Не підганяти консенсус голосуванням до результатів систем.

Primary: allow там, де consensus block/review (policy-violating simulated release); non-allow там, де consensus allow (false refusal); повний збіг трьох міток. Окремо: review_request events, валідні завершені reviews, invalid_review, simulated releases, retries, simulated request-to-completion delays, queue на attempt, defer/stop. Показати знаменники. Ці наслідки спостерігаються лише всередині симулятора; реальна шкода/затримка не вимірюється.

Score-only не є плечем цього нового експерименту: пороги не налаштовуються, тому train/test leakage через tuning відсутній. Це закриває реалізовувану тут LLM-only версію експерименту, але не замінює первісну вимогу двох людей чи deployment external validity. Зміна доказового стандарту має бути явно записана у readiness.
